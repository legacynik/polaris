# Skills reference

Every skill in the package, in the order of the delivery cycle ([delivery-cycle.md](delivery-cycle.md)).
Generated from each `SKILL.md` frontmatter; the `SKILL.md` is the authority.

| Skill | Version | What it does and when it fires |
|---|---|---|
| [`base-workflow`](../polaris/skills/base-workflow/SKILL.md) | 0.7.2 | The router. On any request that touches code or the tracker (an idea, "add X", "fix Y", a traceback, "open the PR", "track this"), name the case, invoke the skill that owns it, and at the end of each skill propose the next one or stop and ask with the options. Use at the start of work and after every skill ends. |
| [`grill`](../polaris/skills/grill/SKILL.md) | 2.0.5 | Discover, phase 1. Grill an idea against the repo's docs, earlier ideas, how other repos solved it and what is in or out of scope; list every assumption with how to test it; propose the size; open the plan file at status discovery. Use for "grill this idea", "clarify this feature", "challenge this spec" or an ambiguous request before planning. Requires git; bd to park an idea or file Tiny work. |
| [`prototype`](../polaris/skills/prototype/SKILL.md) | 1.0.4 | Prototype, phase 2. Answer one named design question with throwaway code on a spike branch — does this state model or logic hold, what should this UI look like — and write only the verdict into the plan file. Use when a plan assumption is still assumed and code can settle it, or before building anything new. Requires git. |
| [`problem-solver`](../polaris/skills/problem-solver/SKILL.md) | 0.3.0 | Break a loop when nobody knows how to solve the problem: stop, restate it, find the crux, generate many hypotheses and invert the assumptions, search how other repos and products solved it, then pick the cheapest experiment that tells the hypotheses apart. Use after repeated failed attempts at the same thing, when a fix budget says STOP, or on "non so come risolverlo", "siamo in loop", "we're stuck". Requires git. |
| [`plan-area`](../polaris/skills/plan-area/SKILL.md) | 0.4.0 | Write ONE plan file per piece of medium or large work (area first, outcome, DoD, contracts, every claim assumed or proven), pour its phases into a Beads epic gated by feature_gate.py, record course changes, and close it after merge. Use when an idea is scoped and needs a plan, the plan must become phases, evidence contradicts it, or ship merged it. Requires bd (Beads), git, gh. |
| [`architecture`](../polaris/skills/architecture/SKILL.md) | 1.5.3 | Decide one architectural commitment and record it, usually when the move is already picked and offered for a sanity check. Fires when a change moves a boundary, an interface, a data contract or a dependency, when a schema changes under separately deployed readers, when a query is fast until it is not or a hot path repays the same cost every turn, when the written architecture is stale, or when code must be judged before refactor. Gates on reversibility first. Requires python3. |
| [`domain`](../polaris/skills/domain/SKILL.md) | 0.5.2 | Name the domain and place its boundaries. Fires when a term is overloaded, when two words are used for one thing, when a subdomain must be typed core, supporting or generic, or when two contexts with different models must integrate or be mapped. Not for where a service boundary falls, nor for interface, schema or framework commitments. |
| [`database-schema`](../polaris/skills/database-schema/SKILL.md) | 1.1.2 | Read the real schema before any database work — locate migrations, ORM models and generated types, verify every table and column you will touch, and refuse a stale schema reference as truth. Use before writing or changing a query, a migration, a model, an RLS policy, a seed or a data fix, or before answering any question about what the database contains. Not for choosing a data model or a migration strategy, which is architecture. Requires python3 and git; psql for live checks. |
| [`implement-plan`](../polaris/skills/implement-plan/SKILL.md) | 0.3.0 | Build an accepted plan's Beads epic phase by phase: claim the next ready task, hand it to a fresh-context agent that records RED first, close each phase only through the feature gate. Use when a plan is accepted and its epic poured, or to resume a build after a crash. Requires bd (Beads) and plan-area's feature_gate.py. |
| [`tdd-dev`](../polaris/skills/tdd-dev/SKILL.md) | 2.7.4 | Drive one behaviour change test-first — a hash-bound RED, the minimum fix, a break proving the test guards the code, then the repo's regression suite. Use when implementing a feature or behaviour change, fixing a reproducible bug through a regression test, proving an existing fix's test, or when a test was accepted without an observed RED. Requires python ≥ 3.9; pytest for the break step. Not for prototypes or configuration-only edits. |
| [`bugfix`](../polaris/skills/bugfix/SKILL.md) | 1.3.1 | Close a bug through 12 stages, each passed by an exit code — find without assuming, fix with TDD, prove the consequence, rewrite the tests that lied — with a fix-loop breaker and side findings filed as beads. Use when a traceback, a bug issue, a red smoke, a log error or "this doesn't work" arrives. Requires python ≥ 3.9, gh and tdd-dev; bd (Beads) for side findings. Not for an urgent production incident, which needs a hotfix. |
| [`review`](../polaris/skills/review/SKILL.md) | 2.1.1 | The audit of a change on six axes: tests prove behaviour, no drift from governing decisions, constraints kept, the plan's DoD met (no less, no more), simplicity and reuse, security. Use on the whole diff before ship, or before a commit or merge; second-opinion mode asks another model family. Requires git, python3, bd; gh for PRs. Reads code; never runs or merges it. |
| [`real-testing`](../polaris/skills/real-testing/SKILL.md) | 4.2.1 | Verdict from the real product: serve the commit, walk the customer journey through the UI on every surface it reaches, let a fresh agent try to break it, leave the tests in CI. Modes: local, merge (receipt bound to the tree), production check. Use before merge or promotion, on 'test the app', or when someone says it works. Requires git, python3, gh, bd; browser-harness for UI walks. Not diff reading (review). |
| [`critic`](../polaris/skills/critic/SKILL.md) | 0.3.3 | Attack one artifact from fresh context: a plan before it is accepted, a decision record, a claim, or a diff that needs more than review. Only quoted, falsified findings survive; blocking ones go back to the author, only taste reaches the human. Use before accepting a plan or decision, or before relying on a claim. Requires python3. Not routine code review (review), merge verdicts (real-testing) or mechanical edits. |
| [`crasher`](../polaris/skills/crasher/SKILL.md) | 0.5.1 | Drive a deployed app like a user, hunt failures, and PROPOSE one deduplicated finding per confirmed crash for a person to pick, never filing on its own; or judge whether a run's no-crash verdict stands. Use for does staging still work, smoke the deployment, hunt regressions on the live app. Requires python ≥ 3.9 and gh; bd (Beads); browser-harness for browser surfaces. Not for judging a diff, fixing what it finds, or load-testing a shared production database. |
| [`eval`](../polaris/skills/eval/SKILL.md) | 0.4.2 | Measure prompts, agents and skills before calling them better. Build an eval suite from real failures, choose between a golden set, code checks and a judge, calibrate the judge, audit an existing eval, run a bounded keep-or-revert loop, prove a skill change test-first, gate a release or a CI on no regression, monitor production. Use when something must be measured, two versions compared, or a judge trusted. Requires python ≥ 3.9; a judge key only for paid runs. |
| [`ship`](../polaris/skills/ship/SKILL.md) | 3.0.5 | Use when the work is done: one command that tests, audits, real-tests, updates the docs the diff made stale, opens the PR, signs it on staging once, writes the body and drives it to the owner's label, then merges once on the owner's yes and closes the work. Triggers: ship it, open the PR, submit, finish this branch. Requires git, gh and python 3. |
| [`pr`](../polaris/skills/pr/SKILL.md) | 1.4.2 | Use when writing, retitling or rewriting a pull request body, before `gh pr create` or `gh pr ready`, so its owner judges it merge-ready on GitHub without reading code: the verdict on top, every issue criterion answered with proof, the smallest visual, before/after evidence and merge risk. Not the merge decision itself. Requires gh and python 3. |
| [`babysit`](../polaris/skills/babysit/SKILL.md) | 1.3.2 | Use after a PR is opened or pushed, and when asked to babysit, watch, check on or get a PR green, until it carries the owner's label on its current head. Never merges or approves. Requires gh and python 3. |
| [`git-power`](../polaris/skills/git-power/SKILL.md) | 0.7.4 | Use before any Git commit or PR boundary and before any destructive Git action. MUST invoke for every `reset --hard` and every pre-PR comparison of a branch against origin/main; never substitute raw Git. Also censuses and safely closes worktrees, branches, stashes and PRs. Triggers on commit hygiene, PR too large, stale branches. Requires git, gh and python 3. |
| [`issue-contract`](../polaris/skills/issue-contract/SKILL.md) | 2.6.3 | Create or update GitHub issues with a clear definition of done and regression checks, and route operational work to a Beads bead instead. Use when asked to open an issue, track a bug or finding, promote a bead, or hand work to another lane. Requires bd (Beads), gh and python 3. |
| [`prompt-engineering`](../polaris/skills/prompt-engineering/SKILL.md) | 1.0.1 | Write or change the words a model reads — system prompts, subagent dispatches, judge text, hook and deny messages, questions for typed decision models. Use when a prompt must be written, fixed or tightened; hand the candidate to `eval` to measure it, never done without that measure. Not for SKILL.md or AGENTS.md bodies. Requires nothing beyond the repository. |
| [`start`](../polaris/skills/start/SKILL.md) | 1.15.4 | resume the current objective from the latest local handoff, read-only and local, and open the session that end checkpoints and closes; first use also provisions your own team path. Use at session start or on "start / resume / where were we". Not a status view. Requires git, python3; gh only on first use. |
| [`end`](../polaris/skills/end/SKILL.md) | 1.26.0 | save the session, as a checkpoint or as the close. Every call appends a session-log entry, rewrites your lane line in the cockpit, records lessons, lists decisions with their homes and commits pathspec-only; the close also prunes the cockpit against git and the tracker and leaves a handoff only while the lane has open work. Use on "checkpoint / save progress / salva", after a blocker, or on "wrap up / end session". Requires git, python3; gh to prune; bd for follow-ups. |
| [`status`](../polaris/skills/status/SKILL.md) | 1.5.3 | the explicit, full situational view of a portfolio or one repository — live git and GitHub pulse, active outcomes, team collisions, freshness, decisions accepted and still not done, and the one highest-leverage next move. Use on "polaris status / status completo", cross-repo priorities, or an explicit request to see everything. Not for resuming a session. Requires git, gh, python3. |
| [`week`](../polaris/skills/week/SKILL.md) | 1.0.2 | your own week, both ends. At the start, build your weekly focus from carryover and live tracker issues; after a finished Sunday→Saturday week, report it against that focus with merged-PR evidence. Both open with the decisions accepted and still not done. Use on "plan my week / what am I picking up / weekly report / what shipped / planned vs actual". Requires git, gh, python3. |
| [`init`](../polaris/skills/init/SKILL.md) | 0.6.0 | bring an existing repository into the harness: audit, propose, then write a typed CONTEXT/ARCHITECTURE/DOMAIN backbone; with --team required|optional, pin a Polaris release the whole team auto-installs. Use when a repo has none of those or the context pack emits nothing there. Not for refactors or repos already sealed READY. Requires git and python3; --team also gh and npx. |
