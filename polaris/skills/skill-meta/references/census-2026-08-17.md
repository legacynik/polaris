## Method, and why the first pass was wrong

Enumeration is mechanical, not sampled: `find -L <root> -maxdepth 2 -name SKILL.md` per root,
then a name-and-description grep for the authoring/eval/packaging job, then two authorities on
provenance — **the installer lockfile** and **the symlink target**.

`~/.agents/.skill-lock.json` tracks 98 installed skills with `source`, `sourceUrl`,
`skillPath`, `skillFolderHash`, `installedAt`. It is the manifest. The first pass judged
provenance by looking for a `.git` directory inside each skill folder, found none, and labelled
three vendor skills "local-only". A missing `.git` proves nothing: `npx skills` installs a
plain folder plus a lockfile row.

The second correction came from `readlink`. Two skills that looked like standalone local dirs
are symlink aliases onto files owned by someone else:

| Looked like | Actually |
|---|---|
| `~/.claude/skills/skillify/` | `SKILL.md` symlinked into `~/.claude/skills/gstack/skillify/` — a gstack-bundled skill |
| `~/.agents/skills/skill-creator/` | the whole dir symlinked into the vendored `obsidian-wiki` package |

Any future census reads the lockfile row and resolves the symlink before assigning a verdict.

## The conflict the house had to settle

The vendor sources disagree on what a description is for, and the disagreement is load-bearing
because the description *is* the trigger.

- `skill-creator` advises a deliberately **pushy** description that reaches for adjacent intent
  ("even if they don't explicitly ask for a dashboard").
- `superpowers:writing-skills` forbids summarising the workflow at all, and cites a
  reproducible regression: a description that described its own process made an agent run one
  review where the skill called for two; removing the summary fixed it.
- `skill-development` mandates literal quoted trigger phrases plus a `version` field.

The house follows the second, which is also what SPEC-MADRE Fase 5.2 already says. It is the
only one of the three carrying a before/after result rather than a preference, and a pushy
description is precisely what `T2a` blocks and what negative controls exist to catch.

## The accepted cost

Absorbing instead of routing means upstream improvements to `skill-creator`,
`superpowers:writing-skills` and `writing-great-skills` no longer arrive on their own.
Maintenance of the absorbed method is ours. Founder decision, 2026-08-17, recorded with the
absorption rows in `CHANGELOG.md`. The compensation is small and deliberate: the
snapshot in `_archived/2026-08-17-skill-writers-absorbed/` with the folder hash, so a diff
against a refreshed upstream shows what we are missing whenever someone chooses to look.
