# Le regole di «Verified clean»

- Verify in the **source on the PR branch** (`git fetch origin <head>` then
  `git show FETCH_HEAD:<path>`, `git diff origin/main FETCH_HEAD -- <path>`), not in the
  diff hunks and never from memory of how the framework behaves.
- When behaviour depends on a library, read the installed library source and cite
  `file:line`. Precedent: `starlette/applications.py:59-71` proved that an `Exception`
  handler is routed to the OUTERMOST middleware, which is what turned "the 5xx alarm
  looks fine" into a confirmed High.
- Killed suspicions from a real run, as examples of what belongs here: two deleted
  frontend test files looked like lost coverage but the component under test was
  byte-identical on `main` and no longer contained the seam (dead tests, correct
  deletion); a missing UUID validation looked like a 500 vector but the column is `TEXT`;
  a widened owner filter looked like an authZ leak but the visibility clause still applied.
- Prefer `symbol` or `file:symbol` references over line numbers for the finding list —
  line numbers in a diff drift; reserve exact `file:line` for library-source citations.
