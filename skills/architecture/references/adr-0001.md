# 1. Record architecture decisions

Date: <YYYY-MM-DD>

## Status

Proposed (the owner sets Accepted)

## Context

Choices about this system's structure, its non-functional characteristics, its dependencies, its
interfaces and its construction techniques get made in conversations and pull requests, and the
reasons are lost. A newcomer, human or agent, then reverses a choice without knowing what it cost,
or obeys one that no longer holds. A record that grows by appended updates turns into a diary
nobody can read as the current state of the system.

## Decision

We will record each architecturally significant decision as one short record in `docs/adr/`.

- **What gets a record**: a decision that affects the structure, the non-functional
  characteristics, the dependencies, the interfaces or the construction techniques of the system.
  Everything below that — a threshold, a method, a prompt, a heuristic, a number — is one line in
  `decisions.md`.
- **File**: `docs/adr/NNNN-kebab-title.md`, numbered in sequence; ADRs live only here. A number is
  never given to a second decision, except when a compaction renumbers the set. A record that needs
  enforcement may carry `probe:` and `probe_kills:` frontmatter: the command that proves it holds,
  and the call site without which that command must fail.
- **Format**: `# N. <short title>` · `Date:` · `## Status` (Proposed, Accepted or Superseded, with
  a `Supersedes ADR-NNNN` / `Superseded by ADR-NNNN` line linking both ways) · `## Context` (the
  forces, as value-neutral facts, measured where possible) · `## Decision` (full sentences, active
  voice: "We will…") · `## Consequences` (all of them, not only the good ones) · optional
  `## Rejected` (alternatives that carry signal), `## Measurement` (when a number decided it),
  `## Not decided` (what the record leaves open) and `## How it would be proven wrong` (the
  observation that would falsify it). One to two pages.
- **The set describes the system as it is**, kept minimal and current:
  - **Amend in place** for drift — paths, names, counts, status, wording reality has outrun. An
    amendment never changes what was decided.
  - **Supersede** for a real reversal: a new record, the old one marked Superseded, linked both ways.
  - **Compact** periodically: merge overlapping records, drop dead ones, renumber. Git history is
    the archive; each compacted record carries a provenance note naming the records it absorbed.
  - **Never append** a dated "update" section to a record.
- **How an area works today** lives in its README (`docs/<areas|modules>/<area>/README.md`), and
  the flows across areas in `ARCHITECTURE.md`; both link these records.

## Consequences

Each decision has one short, current place, and the reason behind it survives the people who
made it. Writing one takes a few minutes per decision, and keeping the set current is a recurring
chore: drift must be amended and overlapping records compacted, or the set rots like any other
document. Low-level choices stay out of the set, so they need `decisions.md` to be kept too.
